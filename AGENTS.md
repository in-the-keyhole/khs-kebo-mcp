# AGENTS.md — kebo-mcp

> **⚠️ Work in Progress** — This codebase is under active development. Expect rough edges.

Guidance for AI agents (Claude Code, Copilot, etc.) working in this repo.

## What this project is

An MCP server that ingests Google Drive documents, redacts client identity, generates local embeddings, and returns aggregated insights. Everything runs on the developer's machine — no external AI APIs, no cloud costs beyond Google Drive (free quota).

## Key architectural decisions

| Decision | Rationale |
|---|---|
| stdio MCP transport only | Localhost tool; no multi-tenancy needed |
| node-llama-cpp for LLM + embeddings | In-process, Metal-accelerated on Apple Silicon; models downloaded directly from HuggingFace |
| Drizzle ORM | Lightweight, TypeScript-first, native pgvector support |
| testcontainers for integration tests | Tests run against real pgvector, not mocks |
| ESM throughout | `"type": "module"` in package.json; use `.js` extensions in imports |

## Directory structure

```
src/
  config.ts          — env var loading + zod validation (loaded at import time)
  types.ts           — shared TypeScript types (StructuredSummary, InsightResult, etc.)
  index.ts           — entry point; wires stdio transport + graceful shutdown
  server.ts          — McpServer definition; registers all three tools
  db/
    schema.ts        — Drizzle schema (documents + document_embeddings tables)
    client.ts        — postgres.js + Drizzle singleton; pass connectionUrl to override in tests
    migrations/      — generated by drizzle-kit; do not edit by hand
  services/
    drive.ts         — Google Drive API (service account auth, search, export)
    redaction.ts     — regex-based PII stripping (emails, phone numbers, dollar amounts)
    summarizer.ts    — LLM prompt + JSON parsing for structured anonymized summaries
    embedding.ts     — node-llama-cpp embedding context; cosineSimilarity utility
    llm.ts           — node-llama-cpp chat session for text generation
  tools/
    fetch-documents.ts  — Tool 1 logic: redact + upsert into documents table
    embed-document.ts   — Tool 2 logic: summarize + embed + upsert into document_embeddings
    query-insights.ts   — Tool 3 logic: embed query + cosine search + aggregate
tests/
  setup.ts           — sets minimum env vars for all tests (no real services needed for unit)
  unit/              — pure logic tests; no DB, no models, no Drive
  integration/       — testcontainers pgvector; LLM + Drive mocked via jest.unstable_mockModule
```

## Testing rules

- **TDD**: write tests before or alongside implementation
- **Unit tests** must not touch the DB, network, or models. Mock at the service boundary.
- **Integration tests** use `testcontainers` to spin up a real `pgvector/pgvector:pg17` container. LLM calls and Drive API calls are mocked with `jest.unstable_mockModule` (ESM-compatible).
- Run tests with `npm test`. All 39 must pass before declaring any task complete.
- Never skip tests to make a build pass.

## ESM + Jest gotchas

- This is a pure ESM project. All imports must use `.js` extensions (even for `.ts` files).
- Jest runs with `NODE_OPTIONS='--experimental-vm-modules'`.
- Use `jest.unstable_mockModule()` (not `jest.mock()`) for ESM module mocking. Dynamic `await import()` calls must come **after** `jest.unstable_mockModule()` calls.
- ts-jest is configured with `isolatedModules: true` for compatibility with `nodenext` module resolution.

## Database

- Schema is in `src/db/schema.ts` — Drizzle with pgvector `vector(1024)` column.
- To change the schema: edit `schema.ts`, run `npm run db:generate`, commit the migration.
- The HNSW index (`embedding_hnsw_idx`) is on `document_embeddings.embedding` using `vector_cosine_ops`.
- `documents.drive_file_id` has a unique constraint — upserts are idempotent.

## Models

- Models are downloaded automatically to `./models/` (gitignored) on first run via HuggingFace.
- Embedding model: `mixedbread-ai/mxbai-embed-large-v1-GGUF` — 1024 dims.
- LLM: `bartowski/Phi-4-mini-instruct-GGUF` — used for redaction + structured summary generation.
- Both are loaded as singletons in `src/services/embedding.ts` and `src/services/llm.ts`.
- Do not call `getEmbeddingContext()` or `getLlamaModel()` in unit tests — they will try to download and load multi-gigabyte models.

## Elicitation

Tool 1 uses MCP elicitation to present a document checklist. The API is `server.server.elicitInput()` (note: `server.server` — the inner `Server` instance on `McpServer`), not `server.elicitInput()`. This is not documented prominently in the SDK.
